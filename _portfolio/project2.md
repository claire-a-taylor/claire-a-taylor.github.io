entry1:
  subtitle: Interact object that enforces altered gameplay
  video: <iframe src="https://drive.google.com/file/d/1j3aMAwWxfJOljIFKlhnLHX27SREbINS7/preview" width="720" height="480" frameborder="0" scrolling="no" seamless="" allowfullscreen></iframe>
  text: I received a request to create a crate 'Heavy Carry Object' that players needed to move between two points during an activity. After creating it we got feedback that it felt bad to be stuck in the middle of enemies without being able to use weapons or abilities for defense, and I was asked to solve for that. I decided to implement the heavy carry object as a heavy backpack instead. I made the previous object delete itself with an effect that made it appear to teleport away, while simultaneously attaching a stripped down version onto the back of the player model and applying the heavy effect to the player as usual. Upon reaching the and interacting with the destination, the model on the player's back would be removed in the same fashion and the crate stack would have its state changed to add another crate onto it. This left the player's hands free to fight as they normally would while transporting the cargo but significantly reduced their movement abilities. Next, I added feedback to the player's screen to indicate to them that were equipped with the heavy backpack in case they were not in 3rd person mode to see it themselves, and also added a network host confirmation signal to the interact to protect the crate from multiple players 'picking it up' at the same time. Finally, a request to give players an option to drop it at any time in case they didn't to escape battle prompted me to dig into the local player data and find an old variable that flipped when players exceeded a certain speed threshold while on the ground and set it to automatically delete the backpack and spawn in the carry object version again at the player position if they exceeded that speed.

entry2:
  subtitle: Interact objects that force player reactions/states
  video: <iframe src="https://drive.google.com/file/d/1RgAWHq90nwUK_EJdvtE5WStiJw4FifGP/preview" width="720" height="480" frameborder="0" scrolling="no" seamless="" allowfullscreen></iframe>
  text: This was a series of invisible interacts I made that could be placed in the world and would force a player's character to take certain actions for a limited amount of time before returning control over to the player. After performing an interaction, a player would receive an attached object that would inject a set of commands into them, suppressing their input, setting their weapons to be invisible, and overriding their camera and their animation state machine to perform a specific animation sequence as dictated by which interact they used. These animations were present in other parts of the game as emotes, but each one either contained VFX that we didn't want or were too long/short to be appropriate. In each case, I needed to make new sequences that inherited from the existing files, but edit them to remove the unwanted features or adjust their timing. After the sequence ended it was important to make sure the injected commands were cleanly deleted from the player character with the proper timing so they not only didn't interfere with subsequent gameplay, but also didn't give the impression of things popping or jerking into place.

entry3: 
  subtitle: Interact object with specific interaction requirements
  video: <iframe src="https://drive.google.com/file/d/1M-90ZLkdQIXNPQUrRTdPRXObcHnsiHq0/preview" width="720" height="480" frameborder="0" scrolling="no" seamless="" allowfullscreen></iframe>
  text: The ask for this object was 'we want an enemy shield that only takes damage from one part of one weapon's attack'. In many instances I had created objects that only responded to a particular damage type, or a particular specially created object, but with how granular the ask for this one was in presented a wonderful challenge to tackle. I had to dig down into the coding for the weapon in question, finding all the damage labels it applied on weapon fire to narrow down the scope of that the shield would respond to. The weapon was created around 8 years prior to this request, so much of the structure for it was significantly outdated and didn't follow modern object conventions. I was able to find a unique set of damage labels to watch for that applied only during the post-firing burst of the ammunition, which fulfilled the request asked of me. Even after creating the object, I spent some time balancing the shield health, regeneration rate, and how often the shield would get reapplied during the encounter script it was used in. Ideally I would have liked to create a cleaner set of conditions for the shield's damage in case another new weapon appeared with the same labels, but since this was for the guaranteed final content update in the game's overall life I decided that my time would be better spent implementing other content instead of proofing for a future that would never come to pass.
